## 1. 项目概述

### 1.1 项目背景

D 系统要成为「人 · AI Agent · 人」控制链的基础设施，从决策层开始，拆解任务，分发任务，并管理人类节点使用合适的工具高效完成工作。

当前 D 系统 2.0 的主要局限：

- 员工自行制定工作任务，工具散落各子系统（CS、Adnext、Auxin、i18n 等），切换成本高，容易遗漏
- AI Agent 能力（Minion / Admin Agent）已具备，但与人工步骤之间缺乏统一协作接口，AI 产出无法自然交接给下一个人或 Agent
- 决策者没有全局视图，团队目标进展、员工工作状态只能靠人工汇报获取
- 各岗位人员没有标准化的任务接收渠道，信息传递依赖 IM，不可追溯

### 1.2 项目描述

**PAP（People · Agent · People）** 是 D 系统 3.0 的人机协作总线。

**核心转变：** 从「员工自行制定工作任务」转为「AI 根据岗位职责主动分派任务，并进行评估和验收」。

**整体流程：**

\[决策者制定目标\] → \[PAP + Agent 拆解编排任务\] → \[一线员工接收并执行\] → \[Agent 辅助执行 / 请求人工介入\] → \[结果验收回流\] → \[决策者汇总监控\]

PAP 针对不同岗位提供专属视图，各视图共享同一套任务分派与 Agent 协作底层能力，呈现上按岗位诉求定制：

| 视图 | 核心定位 |
|---|---|
| 通用员工视图 | 接收任务、响应 Agent 协作请求、跟进执行进度 |
| 财务视图 | 财务专项任务处理（Invoice 审核、JE 确认等）|
| Manager 视图 | 目标制定、任务编排与监控、全局进展汇总 |
| CS 视图 | 客服专属任务流，与 CS 系统集成 |
| 美工视图 | 设计任务接收、资产提交与审核反馈 |

### 1.3 项目有可能成功理由

| 字段 | 内容 |

# 模块一：通用员工视图

面向翻译官、运营等一线员工，提供统一的任务接收与执行引导入口。

**核心能力：**

- 接收 Agent 或系统推送的消息与任务请求，支持状态通知、快捷授权操作、会话协作、跳转执行等多种交互形式
- 待办任务队列（To Do）与当前推进中任务（Doing）的统一展示
- 历史消息可追溯查看
- Agent 在执行过程中需要人工提供信息或验收结果时，通过本视图触达员工并等待回复

---

# 模块二：财务视图

面向财务员工，聚焦财务专项任务的处理效率。

**核心能力：**

- Invoice 审核与确认（含多地区字段展示策略）
- Journal Entry 创建与关联凭证上传
- 财务任务的待办列表与执行状态追踪
- 与 Agent 的协作节点（如凭证自动识别结果的人工复核）

---

# 模块三：Manager 视图

面向决策者，提供目标制定、全局任务监控与 AI 工作情况汇总。

**核心能力：**

- 制定业务目标（Mission），PAP + Agent 自动拆解为可执行任务并按角色分派
- 任务树视图：查看 Mission 下所有步骤的层级结构、负责方与执行状态
- 对需要人工介入的步骤（Agent 执行受阻 / 最终验收）进行决策与确认
- AI Center：汇总各岗位员工工作情况和各 Agent 运行情况

---

# 模块四：CS 视图

面向客服员工，深度集成 CS 工单系统，减少系统切换成本。

**核心能力：**

- 接收与处理用户工单相关任务
- CS 系统任务与 PAP 任务的双向同步
- Agent 辅助处理工单（自动回复建议、信息补全等），人工审核确认后提交

---

# 模块五：美工视图

面向美工/设计人员，聚焦设计任务的接收与产出提交。

**核心能力：**

- 接收设计任务（如活动 Banner、游戏素材等），明确需求说明与 DDL
- 设计资产上传与提交，关联对应任务
- 审核与反馈流转（设计稿提交后等待 PM / 运营确认）

---

## 5. 范围说明

### In scope（Phase 1）

- 通用员工视图：完整的任务接收与 Agent 协作请求处理
- Manager 视图：Mission 创建、任务树监控、人工介入节点的决策确认
- Agent 编排层：Trigger、任务路由派发、subagent 执行闭环（人工节点反向触达）
- 首个端到端验证场景：游戏上线

### Out of scope（后续）

- 财务视图、CS 视图、美工视图（二期及后续）
- 员工工作量 Dashboard
- 移动端适配
- Workflow 自学习

## 6. 风险与待确认事项

| 风险 | 等级 | 应对 |
|---|---|---|
| PAP API 不支持程序化建任务 / callback | 高 | Phase 0 优先验证 PAP 接口能力，必要时推动扩展 |
| subagent 反向触达人工节点的闭环状态机复杂 | 中 | 先在游戏上线单场景跑通，再推广 |
| PAP 缺少服务端实时推送能力 | 中 | 评估 WebSocket / SSE 接入成本，Phase 1 可降级为轮询 |
| 各岗位视图需求优先级未对齐 | 中 | 明确 Phase 1 只交付通用员工视图 + Manager 视图 |

**待确认：**

- 是否资本化，项目周期如何定义？
- 各视图的研发优先级与排期？
- 财务 / CS / 美工视图是否纳入本立项范围，还是分别立项？
