# **模块一：立项**

## **1.1 功能概述**

在A系统中新增「各系统立项」，对各业务系统（A、B、D、E、P、F、Publisher）的研发项目进行统一管理

## **1.2 入口与页面结构**

| **区域** | **说明** |
|-----|-----|
| A系统左栏 新增立项入口 | 目前立项只针对tech部门 |
| A系统中栏  | 快捷卡片「各系统立项」+ 当前系统立项摘要列表 |
| A系统右栏主内容 | 立项表格（筛选、新增、审批） |
| 入口权限 | ~~tech部门General Leader、General Admin、Admin角色~~白名单 |

## **1.3 系统范围**

支持系统：**现有A系统中tech部门的project==，如果区分不开，就获取所有project==**

## **1.4 新建立项表字段说明**

| **字段** | **是否必填** | **说明** |
|-----|------|-----|
| 系统（现有project） | 是    | 单选  |
| 编号  | 自动生成 | 格式 `{系统}{序号}`，如 `P908789` |
| 项目名称 | 是    | 立项名称 |
| 项目描述 | 是    | 项目目标描述 |
| 项目周期 | 是    | 立项日期 \~ 预计上线时间日期 |
| 资本化 | 自动   | 任务类型是新开发的默认是，不强制写死不让改状态 |
| 负责人 | 是    | 支持多人 |
| PRD链接 | 否    | 支持填写多个链接 |
| 任务类型 | 是    | 下拉：新开发 / **维护** |

### **列表字段：**

展示**立项表说明字段外需要添加审批状态、实际上线日期、项目关闭详情、操作**

审批状态：审批中、已通过、已拒绝

实际上线日期：数据通过上线时获取

项目关闭详情：获取oa审批通过后的数据

操作：修改&上线

   修改：审批通过可修改，否则禁用

   上线：审批通过可操作，否则禁用

## **1.5 核心操作流程**

### **① 新建立项**


1. 先选择**单个系统**（非「全部」）
2. 填写：项目名称、目的、项目周期、负责人（默认谁创建就是谁）、任务类型、是否资本化（默认任务类型是新开发的就是可资本化）
3. 填完后「发起审批」按钮可用

### **② 发起审批：**

**新建立项：操作后提示“OA发起成功”**

关闭项目：需要发起OA

### **③ OA审批**

新建立项：


1. OA中展示：编号、项目名称、项目描述、PRD、周期、任务类型、是否资本化

关闭立项：


1. OA中展示：编号、项目名称、项目描述、PRD、周期、关闭原因
2. 审批流：各议员或签---财务人员

### **④ 已审批项目**

| **操作** | **说明** |
|-----|-----|
| 修改  | 可改：周期、任务类型、负责人、关闭项目关闭项目（需设置关闭时间&关闭原因），发起关闭oa，审批通过后数据转入【已完结】tab |
| 上线  | 操作后需设置上线时间，设置后数据进入【已完结】tab |
| 发起审批 | 禁用（已审批不可重复发起） |

## **1.6 立项状态**

| **状态** | **展示** | **说明** |
|-----|-----|-----|
| 无 / null | 无角标 | 未发起审批 |
| 待审批 | 黄色「待审批」 | 已提交，等待审批 |
| 已通过 | 绿色「已审批」 | 可修改 |
| 已拒绝 | 红色「已审批」 | 可修改 |


# **模块二：建 A 卡**

## **2.1 功能概述**

在 D系统 **New Chat** 中通过自然语言指令创建 A 卡（任务票据），建卡成功后展示票据信息与关联立项

A卡：支持并跳转 **A 卡详情页**，由leader确认本项目应归属的立项编号与名称。

**目标**：把日常研发任务（A 卡）与 A系统中 已审批通过的立项建立映射，支撑资本化追溯。

## **2.2 入口与页面**

| **页面** | **路径** | **作用** |
|-----|-----|-----|
| New Chat | `/doraemon-chat.html` | 输入建卡指令，展示建卡成功结果 |
| A 卡详情 | `/a-card.html` | 查看任务、选择关联立项、保存 Output |

## **2.3 建卡流程（New Chat）**

### **步骤**


1. 打开 New Chat
2. 在底部输入建卡指令（示例）：

   建卡，分给我自己，纽约地区假期指南，ddl6月3号，归属p系统
3. 点击 **Send** 或按 Enter

   
   a. 需识别建卡诉求，==匹配A系统中已审批通过且在对应系统周期内的项目==
   b. 只需要将tech部门的卡进行项目匹配，其他部门不需要做该操作
   c. 建卡时间里如果没有对应的项目数据，则提示“没有关联项目”数据
4. 系统返回「**票据创建成功**」卡片

### **建卡成功展示字段**

| **字段** | **示例值** |
|-----|-----|
| 标题  | 纽约地区假期指南 |
| 票据 ID | 1400865 |
| 受托人 | 余斌斌-Yu Binbin |
| 部门  | tech |
| 截止时间 | 2026-06-03 |
| 项目（归属系统） | p   |
| 项目名称 | 纽约地区-新增假勤薪资计算 |
| 状态  | pending |
| 链接  | **G123 - A**（跳转 A 卡详情） |

点击 **G123 - A** 链接，携带 URL 参数打开 A 卡页。

## **2.4 A 卡详情页**

### **页面新增**

新增项目名称和项目编号ID，支持更改对应系统下对应时间周期已审批通过的项目。

### **项目编号 / 项目名称（核心交互）**

两个下拉框**联动**，数据来自 **模块一** 的立项列表。

**筛选规则**（同时满足）：


1. **归属系统一致**：URL 中 `system=p` → 只显示 **P 系统**立项（非固定 A 系统）
2. **周期有交集**：立项预计周期与任务周期有重叠才可被选

示例提示文案：

> *可选范围：P 系统 · 任务周期 2026-06-01 至 2026-06-03 内的立项（共 N 项）*

如果更改system，已匹配的项目名称和编号清空，默认选中第一个
